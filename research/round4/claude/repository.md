## 对 IM 适合的小机制（独立描述概念，不复制代码；GPL-3.0 下不引入代码）

| jrnl 机制（概念） | IM 对应的候选小机制 | 落点 |
|---|---|---|
| 自由文本内嵌 `@tag`，词边界正则提取、小写归一、集合去重；正文原话不动，标签只是元数据 | 适配流水/反馈条目在原话后补内嵌标签（如 `@偏好` `@观察` `@试用`），摘要照抄原话不转写，标签用于回看筛选 | adaptation-loop 最小观察字段 |
| `*` 星标：一行内的轻量标记，与标签正交 | 用户明确说"这条以后都这样/这是硬边界"的条目加星，区别于普通流水；复审时不重审整档案只看星标条目 | 画像"明确偏好/边界"区 |
| `filter()` 组合查询：标签（任一/全部）、排除、日期窗、星标、包含文本，一次过滤 | 周复盘/复审时"只看本类目的试用条目"按组合条件取，不人工翻账 | imsupervisor 复盘、imreflect 反馈分析 |
| 最小条目结构 = 日期 + 标题 + 正文，纯文本可追加，人类可直接读改 | 现有"日期\|任务\|观察\|下一步"字段已满足；jrnl 十余年生产使用佐证该最小结构可持续，无需加字段 | 维持现状（避免过度设计） |
| 多命名日志（一个 config 管多账本） | 套件已有"每线一份总览 + 单一写入者"约定，结构等价；不引入新概念 | 维持现状 |

## 明确排除项

- **不引入整个 journal 系统**（存储格式、加密、编辑器、命令行界面都不需要；IM 的账本是 Markdown + 对话）。
- **不复制任何代码**（GPL-3.0 传染性；候选文档只以文字描述机制概念）。
- 不引入"每日必须写日志"的默认节奏——jrnl 用户可以一天多条也可以不写，这与 IM"可跳过"原则一致，恰好说明轻量标记不强制频率。
- 未运行 jrnl 程序本体（约束：不运行陌生代码）；机制结论全部来自静态读源码。

## 对候选的具体改动建议（供 Codex 整合时取舍）

1. feedback-loop.md 的"反馈记录格式"建议采用：`日期 + 用户原话摘要 + 内嵌标签（@偏好/@观察/@试用）+（可选星标）`，替代另起结构化表格——与 adaptation-loop 最小字段兼容，只是明确标签词汇表。
2. 唯一新增字段建议：今日计划块内一行 `反馈: 未邀请/已跳过/已答（指针）`，用于"每日一次"去重；不新增全局状态字段。
