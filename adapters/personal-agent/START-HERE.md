# 将IM交给Dot、Grok Bot或其他个人agent

这是可移植规则包的接入说明，不是已经开通的云服务。保留完整skills/和shared/结构，研究原文、备份和个人记忆不在分发包内。

## 可直接交给宿主的指令

“请读取这份包中skills/using-im/SKILL.md及当前任务需要的引用，按它路由教学、规划、执行复盘、自愿意义探索、轻松交流、项目推进与智能体协作。复用工作栈前先预览并取得本次同意；无桥接、有效权限或模型选型证据就如实说明，不默默换宿主。首次正式使用先互动了解我的当前重点和约束，已提供的信息不重问，不替我填人生目标。

先告诉我：你实际读到了哪些组件；能访问哪个学习状态正本；哪些读写/提醒能力已经验证，哪些未知。沿用已有学习目录，不把此源码目录当个人档案。只有同一份skill不代表进度已同步。

需要长期保存时，与我对齐状态正本IM_HOME的实际位置和共享范围；跨宿主默认一个写入者，另一方提交提案。未连接前不要上传或声称同步完成。没有数据访问就给“本轮未核实同步”的状态卡。

我明确要求设置提醒后，请用你真实的调度器；缺时间就先问，保存后报任务ID、时区、日程和渠道。不把本地草稿当已建提醒，也不以未回复判我没做。”

## Dot路径

如使用本机已安装技能，先在Dot中连接并授权该电脑，再要求其使用using-im并读取实际来源。电脑需在线才能访问本地资源；只在手机登录不会使D盘文件变成云端文件。可在Dot官方界面查看连接电脑与Scheduled，实际账户是否可用需当场核查。

## Grok Bot路径

将规则包放入Bot能读取的位置，或按其原生“保存技能”流程建立入口并确保引用可读。不要假设本zip有一键导入兼容性。首次先跑一轮初始化/续课检查，再创建需要的routine。原生技能共享与内置记忆不等于IM在不同产品之间自动同步。

## 验收

1. 第一次给目标 → 分轮追问并等本人答，不凭空填档。
2. 换设备/宿主 → 实际读到同一状态revision与知识账；不可读则明确本轮未核实同步。
3. 新增普通偏好 → 在授权正本保存并在另一端重新读取验证；不要用私密原话作探针。
4. 明确设置提醒 → 核对真实调度任务与接收渠道；如果测试投递，区分调度已保存和本人收到。

本轮只验证规则/文件分发。以上涉及真实账号和云存储/通知的测试尚未执行；选定宿主、状态服务与提醒时间后，才能作对应端到端验收。

原学习与个人发展组件共用feedback-loop：计划完成制定后通常邀请建议一次，可跳过或更改触发点；不叠加反思/心情问卷。用同一正本记录实际邀请日期才可能跨设备去重；无状态访问只做当轮去重。聊天或反思不默认写私密日记，不改计划正本。

## 可选：在宿主上试用后台接续

让具备队列访问权限的宿主读取 [后台接续协议](../../shared/background-followups.md)。用单独的私有测试队列和结果区；例如在用户自己连好 Notion 后，只绑定指定测试页，先手动验证空、单条、重跑和失联。不得扫描其他页面或索引历史聊天。未连接时可用本地虚构数据演练，结果不代表已跨设备同步。

给执行宿主的入口：“只从约定队列认领一条已授权、到期且未过期的任务，结果按任务 ID 去重。空队列静默；源不可达记受阻；默认不浏览、不调其他模型。不修改正式学习进度。运行结果写到约定私有区域。按我的时区和频率授权再开定时运行。”
