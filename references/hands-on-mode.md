# 实敲模式 · 任务设计与 debug 教学

## 两种模式

- **实敲模式**：机器能跑。学习者亲手执行，贴输出回来。
- **纸面模式**：机器不能跑。给出命令与"假想输出"，学习者在纸上 trace。
  两种模式教学内容等价，实敲多出"真实 debug"这个宝藏，条件允许永远选实敲。
- 模式记录在留痕；条件变化（电脑修好/环境就绪）时切换，已用纸面学过的概念
  补一次实敲验证。

## 实敲任务设计模板

```
🔬 实敲任务 N：一句话目标

【先预测】要观察的 2-4 个具体点（预测错了才是最大的学习时刻）

【命令块】可直接复制的完整命令（heredoc 建文件时注明 EOF 顶格纪律）

【交什么】预测 + 完整输出（报错原文也要）
```

设计要点：

- 命令块必须可直接复制运行，不出"自己想办法"的模糊任务
- 故意制造概念证据：让输出里藏着本课知识点的可见痕迹
  （如 chmod 644 目录后 ls 的"错误+文件名并存"双行输出）
- 对照实验优先（cp 前后 inode 对比、删原文件后两种链接命运对比）
- 每个实验都该有一个"如果只听讲看不到、亲手跑才见得到"的点

## 预测-对账纪律

- 只交预测不交输出 → 退回补交（实敲纪律，温和但坚持）
- 预测与输出矛盾 → **以输出为准**，并指出学习者自我修正的行为
- 预测全对 → 也要让证据落地（"跑一下盖章"），概念过了也要见数字

## Debug 教学（卡住/报错 = 教学机会）

处理流程：

1. **先教急救**：卡住 → Ctrl+C；假死判断 → 按回车看提示符是否响应
2. **教定位工具**：bash -x / python -u / 分段注释执行 / 查看中间状态
3. **让学习者贴现象**（报错原文、trace 停住前的最后几行），**引导定位而非直接给答案**
4. **破案后总结**：凶器是谁、为什么它不报错（静默错误比卡死更危险）、
   下次的防身写法 → 记入留痕
5. 报错解码库随教学积累（unary operator expected = 变量空；command not found =
   空格分词把赋值拆了；Permission denied = 权限/目录 x 位……）

## 静默错误专题

不报错但错的代码是重点教学对象：

- 现场案例（如 `echo i=0` 代替 `i=0` → 循环静默跳过）值得单独复盘
- 教学：trace 模式让静默错误现形；"有感觉的错误（卡死/报错）是好错误"

## 工具随手教

实敲中顺路教真实工作流工具（不单开课）：nano 三招（编辑/Ctrl+O/Ctrl+X）、
heredoc 建文件、管道串查、trace 调试。这些是 Assignment/工程的真实地基。
