# IM Cowork：识别和复用工作栈

工作栈是可命名的协作配方：任务类型、谁负责哪一步、交接什么、怎么验收。复用的是分工规则，不是历史授权、某段对话或某次连接。

## 识别与保存

1. 只使用当前对话和用户已允许读取的工作记录、交接卡或产物。对照的是相近任务的分工、交接顺序、验收结果和实际代价；同一工具名频繁出现、同一次任务的重试、只派发未收到结果，都不能证明搭配可复用。不得为找模式扫描其他私聊、宿主或未授权项目。
2. 相近任务有多次独立且可核对的成功时，可以提名；若用户直接命名，也可建一条未验证候选。一次只提最符合的一套；不确定就不用猜。不要因为出现次数多就推断更省时或擅自升级成默认。
3. 用户同意保存后，才在其已授权的私有工作正本记录一张卡：名称与版本、匹配/不匹配条件、各角色及建议宿主、必要资料和交付物、模型档/费用与重试约束、验收和已同意的降级选项、证据指针、状态与复审条件。只存最小摘要，不存聊天全文、访问令牌或历史授权作为凭证。没有可写私有正本就给可复制卡；不写入公开技能、另起同步源或自动上传。
4. 用户说停用就停止推荐；条件或桥接变化、效果下降时标待复审，保留最近反例。更换角色/供应商、读入新的资料类别或新增外部操作时，新版先给用户看。个人配方不自动修改全局技能或别的项目。

## 每次启用前只问一次

在绑定任务、发给工作者、入队或新开后台执行前，先用一两句给本人看：哪套工作栈及版本、这次谁做什么、传什么资料、写到哪和怎么验收；费用/时限或不可用时的替代会影响决策时一起说清。按当前可见能力说明模板与实际可用角色、模型档或权限之间会影响本次的差异；未核实的地方说未知。角色名只作提示，有条件时用宿主、账号和可核对的定义或版本来锁定。用户只点名“用这套”时，仍先给这次的短预览。

- 只有来自获准身份、能明确对应当前预览的同意，才覆盖该任务的一次运行。将同意和任务 ID、模板版本、参与者、资料范围与交付去向关联；拒绝、沉默、旧消息、其他人转述或对另一张卡的“好”都不能启动。一个会话有多条待确认时，要求指明任务。跨会话挂起须有明确失效时间；没有可靠的挂起状态，只在当前会话等待，回来时重新预览。
- 执行前复核当前工作者的实际定义、工具、权限和模型选型；同时满足模板约束、本次同意、项目和宿主政策。工具仍能越过预览中的读写或投递边界时，即便确认了也不派。批准后的原范围内无需逐步再问；重放批准、超时或重连先查运行记录，以任务 ID 和步骤 ID 去重，不新起一轮。换人、换供应商、发更多资料、写到新地方，或增加费用/副作用超出刚才同意的边界时，先暂停并给更新后的预览。明确已经同意的降级不另问。
- 桥接不可用且没有获准替代时，只继续原任务已授权的本地部分，或给可复制交接。不得把任务发给另一个 agent 碰运气，也不能把旧记录当成今天已经连通的证据。交付时用一句话说明实际参与者和影响结果的替代或缺失；宿主未报告实际模型则记未知。

示例（候选，未保存）：**IM 研究双审**。Claude Code 查一手公开资料，交来源和限制；Codex 独立核对并整理候选改动。可问：“这次用『IM 研究双审』吗？只把这两条公开链接和问题发给 Claude，由我复核后整理到候选稿；桥接不通就由我查，不换其他服务。”同意之后才派发。
