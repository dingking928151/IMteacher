# IM Cowork：按目标和实际工具构筑工作流

用于“根据我的需求和现有工具搭一套流程”“把这个工作流改得更合适”。即使最后只有主会话和一个脚本，也可以构筑。普通小任务直接完成；项目步骤的实际交付与科研验收归 imwork，时间优先级归 implanner。构筑是可评审产物，不等于调用其他 agent、入队或开始执行。

## 1. 先确定交付，再核实能力

复用本次已有目标、输入正本、验收、时间/费用/算力限制和允许的读写范围。只问会改变方案的缺口。先看当前获准材料中是否已有适配的流程；合适就引用和局部改造，不为构筑而重建。

只核对当前任务所需的能力：工具/技能、模型和桥接、数据/环境、存储与真实执行权限。用当前宿主提供的接口、实际读到的技能、配置说明或低影响探测作为证据；旧任务记录、图标或模板中的名字只能提供线索。安装了技能不等于账号连通，工具存在不等于获准使用。

能力表按需要简写：**能力、当前证据、限制、可用/未知/不可用**。例如终端可用但只有 CPU；Claude 桥接不可用；第三篇论文仅能读摘要。不要为做清单扫描其他私聊、整个磁盘或凭证。确需安装、开服务、增加费用或扩大访问时先列缺口，按实际授权处理。

## 2. 交出最小可行步骤

先给一行依赖顺序，再给足以执行和验收的步骤表；短任务可压成一两步。确定性转换、校验、查询优先用现有工具/脚本，主会话负责解释和判断；只有符合主技能派发条件才安排工作者。流程图中的角色是拟议分工，不代表已调用或具备隔离。

每个将被执行的节点至少能回答以下问题；已有项目字段用指针引用，不反复填表：

| 节点内容 | 应明确什么 |
|---|---|
| 步骤 ID、依赖与输入 | 等什么先通过，使用哪个来源/版本；失败的上游不能当作成功输入 |
| 执行者、实际工具与读写范围 | 谁操作、当前可用接口、必要资料和允许产物位置；主会话可独自执行 |
| 输出与验收 | 应产出什么，凭哪条命令、来源核对、产物或本人判断过关；自报完成不算核验 |
| 预算、停止与失败路径 | 本步在总预算中的限额、重试上限、何时停；已允许的替代、手动交接或阻塞 |

并行只用于输入已就绪、互不写同一产物且确有收益的节点；试点仍按主技能单层、最多两个并发的约束。依赖边表示验收通过后才能进入下一步，不能用“已经派发”代替输出。跨会话继续保持正本的唯一获准写入者。

费用、时限、算力和调用次数按**整个运行**汇总，包含并发、调试和重试；不得把一次预算复制给每个节点。无法估算就说未知，并给预算内能做的部分或小试提案；不声称必然省费。模型档位遵循主技能，不因画了流程就自动换服务商、增加权限或开启小模型。

## 3. 版本、准备状态与执行授权

持续/可复用工作流用已有任务正本保存：**任务/流程 ID 与版本、目标和验收、输入/能力证据、步骤依赖、参与者与资料范围、预算/停止、产物与核验、下一步**。只有有保存权限才写，否则给可复制卡；一次性讨论无需建库。

设计中的每步分清：

- **可执行草案**：相关前置和能力已核实；仍按本次真实授权决定是否运行。
- **待授权**：数据转交、工作栈调用、费用或外部操作尚未获准。
- **缺能力/待核实**：接口、输入、环境或权限能力缺失，明确手动路径或依赖；不能画成自动可执行。

用户只要求构筑时，交出草案与关键缺口即完成本次。用户要求执行时，已经获准的本地主流程按范围推进，不为每个步骤重问。准备绑定/派发工作栈、交给其他 agent 或入队前，按 [工作栈规则](work-stacks.md) 展示**当前版本、参与者、分享资料、写入去向、验收与会影响决策的成本/替代**，等对应本次的明确同意。同一运行已批准范围内的步骤不重复问。

输入版本变化先检查受影响的产物；同意不能覆盖新增参与者/供应商、资料类别、写入目的地或超限费用。此类变化暂停相关分支，给更新后的预览。已同意的降级可直接使用。桥接失败时只用已允许的替代或继续原本已授权的本地部分。

## 4. 留下真实状态，可靠恢复

执行中分开记录：未开始、运行/排队（须有真实宿主记录）、产物待验、已核验，以及失败/受阻/待本人决定。代理会话结束、报告 ready、文件存在都不自动完成任务；核验与真实外部回执另外记录。

- 有事件来源时关联来源消息/事件 ID、任务 ID、流程版本、步骤 ID 与已有运行。相关上下文只补充证据，不授予新权限；重放同一事件或批准先查对应运行，不新开一轮。没有可靠事件标识或可核查运行记录，就不自动重试有副作用的动作。
- 重连先读正本/输入版本、检查已存在产物、运行日志和外部回执；复用仍有效的已核验步骤，只重做受影响或确实失败的部分。外部结果未知先查询，不能盲目重发。
- 用版本或备份保留已有工作和用户改动；流程规则不授予删除、重置或覆盖权限。恢复失败时给当前证据、缺口和一个下一动作，不假装已回滚或已取消。
- 撤回、预算耗尽或越界时停止新调用，记录正在进行和已经发生的操作；需要终止真实任务时核实宿主结果。后台或定时只能按 [后台接续](background-followups.md) 接入真实队列，不用工作流文字模拟常驻路由器。

## 5. 小试、复用与成长

先用虚构/非敏感输入和最小步骤检查关键连接、失败路径与验收。真实执行再分别记录质量、时间/费用、遗漏与人工干预；工具断连与方法不合适分开分析。一个更快但漏必需证据的流程不能因“成功率”好看就降验收标准。

反馈按 [适配流程](adaptation-loop.md) 转成一个可撤回的局部改动；不够证据就保持候选。用户同意保存惯用配方后，按 [工作栈规则](work-stacks.md) 记录版本、适用条件、反例和复审触发；保存不等于下一次自动运行，个人经验不自动改全局技能。获准且验证过的项目工具用法写到既有项目说明，不复制私人聊天全文。

例：“三篇 PDF → 小实验 → 一页简报”，两篇全文可读、GPU 未知、Claude 断连。先由主会话整理来源与假设，再检查基线环境；CPU/合成图只能做跑通小试，正式比较按 imwork 的科研规则。最后核验结论与原始输出再成稿。此时交的是分阶段草案；第三篇缺全文、算力未知及桥接断开各自标明，不宣称训练、派发或同步已经发生。
