# 代码三段式 · 详细规格

三段是可选的帮助方式，不是必须依次通关的仪式。先给完整任务，让学习者独立思考/写代码；用户要求先写时不先泄露参考程序。根据实际缺口选择读码、补全或独立编写；已有相应证据就跳过多余支架，初学且需要示范时用独立示例。细则见 [教学设计](teaching-design.md)。

## 段一 · 读码标注

给一段参考代码（教材的/经典的），要求学习者逐行标注：

- 这行干什么（用自己的话，不抄注释）
- 关键变量/张量的 shape 或类型
- 特定标记任务：如"给四步曲的每行标步骤号"

批改看两点：术语用没用对、有没有行是"不知道"。
"不知道"的行 = 段二的挖空重点。

## 段二 · 填空/选择

把参考代码挖空，优先挖：

1. 参数位（`nn.Linear(784, ___)`）
2. 顺序位（四步曲哪行在前）
3. 易错点（`-=` vs `+=`、丢乘号、丢逗号）
4. 概念位（这段在循环外还是循环内）

批改后：错误分类施治（拼写类直接给正确版；约定/概念类讲原理），
记忆型错误配读法，然后**必须出迷你验证**（2-4 道变式重答），记录本次帮助程度；能自行选择下一步时减少提示，随后用未泄露答案的新任务检查独立性。

迷你验证示例：改数字问 shape（`nn.Linear(300,88)` 的 W 是多少）、
删参数问缺什么、改结构问要动几处。

## 段三 · 终局手搓

任务书只含四样：

```
① 任务规格一句话（"写一个 784→H→10 的 MLP 训练脚本，5 epoch，SGD lr=0.1"）
② 允许抄的段（数据加载等 API 记忆型内容，明确说"这段不用记"）
③ 自查清单（交卷前自己过的硬性项：标点/顺序/shape/易错点）
④ 验收题（2-3 道概念应用题：如"参数量算式""某现象排查顺序""一句话部署方案"）
```

规则：

- 参考代码收起来，从 import（或指定起点）独立写
- 第一轮提交错误多是**预期内的**——开场就说"这是收获清单不是失败"
- 批改输出错误清单表（分类 + 你的 vs 正确的），然后：
  - 第二轮默认**修自己的代码**而非重写（保骨架、练 debug 眼）
  - 学习者要求先看独立示例完整版可以示范；合上即时默写只记即时回忆，须相关独立应用/解释，延迟迁移另查；不代做提交稿
- 分别记录本次独立程度、解释/应用与实际测试，通过范围明确后再衔接下一单元；修错数量只描述修订过程，不能单独证明独立掌握

## 与单元主线的衔接

三段式对象 = 本单元的核心代码资产（一个训练循环/一个脚本/一个数据结构实现）。
段三的独立完成、测试和解释分别记；只对已检查的任务范围作判断，延迟保持/迁移另验，与知识点证据分开记账。
