# IM 共享状态与协作约定

## 位置与兼容

使用用户指定的项目/学习档案根目录。先找已有 IM 状态与 TMP 备忘录；只有需要跨会话规划且没有状态时，才建立 `IM_STATE.md`。未能读文件时在对话中给可复制状态卡，不编造已经读取或写入。

已有教案、画像、各线总览仍是其领域的正本；状态只记索引、必要摘要和下一动作。旧学习档案不自动迁移。规划目标尚未明确时，不把当前目录或聊天内容擅自当成完整人生档案。

## 必需字段（按任务需要填写，未知可留空）

```yaml
schema_version: 1
state_revision: 0 # 可选：所有状态更新的版本；不等于已实现条件写/锁
updated_at: YYYY-MM-DDThh:mm:ss+08:00
timezone: Asia/Shanghai
mode: standalone # 或 suite
plan_owner: imteacher # suite 时为 implanner
plan_version: 0
day_opened_on: null # 首次制定当日计划时写当地日期，独立于 updated_at
active_track: null
sources: [] # 路径、最后读到的日期；原始学习记录不在此重抄
adaptation_source: null # 可选：现有画像/适配流水的唯一正本指针
onboarding: null # 可选：status、reviewed_at、known_fields、deferred_fields；旧记录缺省不代表新人
runtime_binding: null # 可选：宿主、正本资源映射、唯一写入宿主、已实际核查能力；不放凭据
interaction: null # 可选：feedback_offered_on、偏好正本指针；没有此字段不代表新人
reminders: [] # 可选：owner_host、真实schedule_id与核对摘要；不是调度器
directions: [] # 用户原话/已确认方向、约束、探索假设、复审日期
tracks: [] # id、状态、账本路径、next_step、现有证据
today:
  date: null
  available_minutes: null
  tasks: [] # id、动作、预计分钟、验收证据、状态、关联方向/阶段目标
execution: [] # task_id、何时、用户自述/实际可见证据、结果、阻碍
proposals: [] # 提案与待确认取舍，不能冒充已批准的新计划
next_action: null
```

上例日期/时区随用户当前上下文选择；不要把占位符、示例目标或推测的考试日写成事实。没有预算时，可以给明确标注假设的暂定方案，不能声称用户承诺了该时长。

## 读写职责

| 组件 | 写入内容 | 交接 |
|---|---|---|
| using-im | 当前路由/负责人、来源指针 | 把相关最小上下文交给被选组件 |
| implanner | directions、tracks 的计划字段、today、plan_version、day_opened_on | 交目标任务和验收标准 |
| imteacher | 学习账本、画像与 tracks 的学习证据、next_step | 返回实际掌握证据/阻碍；不代填计划完成 |
| imsupervisor | execution、阻碍、proposals | 将需重排的建议交 planner，不自行改计划 |
| imreflect | 经本人确认可保存的理解/未决问题摘要或指针 | 准备承诺行动再交planner，不直接改directions/today |
| imcompanion | 经授权的最小互动偏好，通常无需保存聊天 | 按本人意愿切换，不建心理诊断档案 |

interaction由当前唯一写入者维护，反馈日期只在实际邀请后更新；所有组件共用同一画像与[每日反馈协议](feedback-loop.md)，不是各建每日问卷。对话选择与频率偏好保存在既有画像正本；仅闲聊不为此强制读写状态。

独立 imteacher 未使用套件时，可继续写原有日开与预算。用户显式采用套件或已存在 suite 状态时使用分工；新组件缺失时说明降级方式，不声称已调用不可用 skill。

## 独立teacher的反馈落点

仅使用旧TMP、尚无IM_STATE的独立模式，不为反馈强制新建套件状态。在同一份TMP备忘录的“互动元数据”节记录feedback_offered_on（实际邀请的当地日期/时区）及画像正本指针；它不是日计划，不写进各教学线重复保存。已有IM_STATE时只用其interaction，不维护两份日期。切换suite时迁入已确认元数据一次，TMP该节改为正本指针；迁入前核对是否同日已邀请。无权限或用户不愿保存时只做本轮去重，不声称跨会话保证。

## 日期与多会话

以宿主/客户端在本轮明确注入的当前日期与时区为准；这里不指旧对话中记忆的“今天”。缺少当轮可靠日期、会话实际跨午夜而未刷新或出现冲突时，用工具核实并换算到用户时区，不用另一台机器的时区直接覆盖客户端信息。日程用 `YYYY-MM-DD`，倒计时现场计算。`updated_at` 表示最后更新，不能当作“今天已经日开”的证据，日开看 `day_opened_on` 和 `today.date`。

suite 的当日计划正本为 `IM_STATE.md` 的 today；旧 TMP 的“今日计划”只留指针/只读摘要，并注明非计划正本，不由 teacher 维护另一份任务状态。独立模式沿用 TMP 的“今日计划”正本，套件切换时只迁入已确认的当日计划一次并更新指针。

读取后记录 plan_version；写前重读，版本变化则先合并各自字段，不能覆盖其他组件的新结果。此约定并不提供文件锁；多人/多会话并发时指定单一写入者，其他会话只交建议，不能宣称原子并发安全。

用户新报告与旧档案冲突时列出冲突，确认是否发生了新进展；旧档案不自动压过用户当前描述。分别保留“用户自述”与“已见证据”，时间旧也不等于知识失效。

## 证据是维度，不是单一等级

| 证据 | 能支持 | 不能自动支持 |
|---|---|---|
| 看过/听过/做笔记 | 接触过材料 | 能独立解释或应用 |
| 无提示独立作答 | 本次题目/任务的表现 | 长期保持、迁移到新情境 |
| 编译/运行 | 该环境该输入的执行结果 | 逻辑完全正确、独立写成、平台通过 |
| 平台判题通过 | 该次提交通过该平台测试 | 理解原理、独立完成、其他题型掌握 |
| 延迟变式重做 | 对该概念的保持与迁移证据 | 所有相关能力都已掌握 |

记录日期、题目/任务、帮助程度和证据来源。助手自己的测试、用户自己提交、未知结果分开记；用户说“完成”可以记自述，不能伪造验证。

## 计划与自主权

用户决定什么值得做；AI帮助展开选项、看清代价与验证假设。重大改变既定方向、放弃课程、长期加量等，说明理由、后果与替代方案后确认。正常任务排序可在已授权预算内执行。

反思内容由用户作答，AI不代填价值观或推断潜意识。持久化以必要的方向/约束/行动摘要为主；私密原话可只留在当轮，用户选择再存。不凭“没有回复”判定失败，不凭欠账贴人格或心理标签。

默认监督发生在用户互动时；只有已配置且明确授权的提醒/自动化才能宣称会主动提醒。

## 个体适配

需要调整讲法、复习或估时时，按 [个体适配与方法改进](adaptation-loop.md) 区分明确偏好、观察/试用与有限情境的个人默认。保留反例、帮助程度和复审触发；个人参数变化不直接修改全局技能。状态只索引画像，不重复持有一份效果账。

## 首次使用与外部宿主

首次采用套件或明确要求设置时按 [互动初始化](onboarding.md) 分轮了解目标与约束，复用已有记录；简单答疑、工程咨询与续课不强制访谈。直接调用组件时也沿用同一份初始化状态，不各建一份画像。个人数据保存沿用用户授权与当前环境权限。

Dot/Grok Bot等宿主、跨设备访问和提醒按 [宿主接入](agent-runtime.md) 核对真实能力与正本。state_revision是可选记录字段，本文件不提供同步服务器、调度器、通知服务或文件锁；这些能力未实测就保持未知。
