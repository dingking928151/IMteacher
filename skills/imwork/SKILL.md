# IM Work：项目推进与交付

先明确当前项目、下一件要交付的东西，以及怎样算完成。用户已给足信息就直接开始；只追问会改变下一步的缺口。一次性小任务直接处理。首次持续协作才约定正本、能保存的范围和需要本人决定的事，不要求建立完整档案。项目执行归 imwork；跨项目的时间优先级归 implanner，根据目标与可用工具构筑工作流、派发与常用协作栈归 imcowork。

## 工作正本与交接

- 只有持续或跨会话工作才用任务单：项目/任务 ID、交付物和验收、正本及输入版本、可读/写范围、预算和停止条件、已验证证据及下一步。默认不扫描旧会话；不能访问来源就给可复制交接卡。
- 继续任务先核对正本版本。旧结果保留为历史，重新核对受影响部分；由获准的唯一写入者更新正本。工作记录与学习状态、私人关怀分开；多宿主接续用 [宿主约定](references/agent-runtime.md)。
- 排队、运行、产物待验、核验、对外交付是不同状态。记录真实命令、日志、截图或产物版本，分别标注自动检查与人工复核；没有证据就保留待验。对外操作只按实际授权执行，回执未知先查询，不能盲目重发。
- 先手动触发。只有用户请求、宿主确有能力且满足 [后台接续约定](references/background-followups.md) 时，才能考虑真实队列或调度。需要派发、换宿主或用惯用工作栈时交给 imcowork，由它处理预览与当次确认；组件不可用就做已授权的本地部分。

| 工作 | 怎么推进 | 验收重点 |
|---|---|---|
| 开发 | 明确复现或验收，核对基线，在授权范围内隔离修改，跑相关测试。 | 变更和基线、测试范围与日志；失败、跳过和未运行分开。涉及 API 边界或历史决定时说清要人判断什么。 |
| [科研](references/research-cycle.md) | 明确问题与可被否定的假设，约定比较协议；先核基线再小试，按证据和预算决定扩大、消融或停止。 | 声明对应真实来源、运行与版本；核对数值、评价协议、引用和方法—代码一致。跑通、可复跑、结论受支持分别验收，负结果也可交付。 |
| 视频与社交 | 从脚本到素材、剪辑或字幕，再到可审的标题、简介、导出或发布包。 | 素材来源、版本、尚缺的授权。准备好发布包仍是待发布。 |

收尾交一条下一动作和仍需确认的点。反馈有助于下一轮时可询问一次；按 [适配流程](references/adaptation-loop.md) 处理事实纠错或一次可撤回试验，不因一条意见重写全局技能。
