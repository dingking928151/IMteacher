# IM：科研与工作流使用卡

这是一页使用说明和可复制的展示样式，适用于 IM v0.7。下面都是自然语言请求示例，不是已经注册的快捷命令或新插件按钮。

## 不必记住技能名

| 你想做什么 | 可以直接说 | 当前负责人 |
|---|---|---|
| 学懂内容 | “讲懂这篇论文的聚合方法，沿上次进度继续。” | imteacher |
| 推进科研 | “检查这个实验比较是否公平，哪些结论有证据。” | imwork，按需读科研闭环 |
| 构筑流程 | “根据我现有的工具，把这三篇论文到小实验和简报的流程搭出来，先给草案。” | imcowork，按需读工作流构筑 |
| 复用配方 | “看看本项目有没有合适的已保存工作流，给这次的简短预览。” | imcowork，核对当前版本与能力 |
| 只做小事 | “把这三条摘要做成表格。” | 直接处理 |

触发依据是本次意图，不是出现“科研”二字就启动全流程。宿主必须发现并加载技能才会采用规则；技能文件本身不是常驻监听器。构筑不等于运行，学习论文不等于启动实验。

在已发现这些技能的 Claude Code 会话中，也可在消息开头直接输入 `/imwork`、`/imcowork` 或 `/using-im`，后面写本次需求；不想记名字时仍可用上表的自然语言。自动选择依赖技能描述和当前会话，未选中时直接调用即可，不保证每次自动命中。

## 想看得清楚，可以让它显示这张卡

> **工作流草案：论文 → 小实验 → 一页简报**
>
> **目标**：得到可核对的初步观察与局限。
>
> **步骤**：核来源 → 定问题/协议 → 基线小试 → 必要比较 → 核证据 → 简报。
>
> **分工**：主会话负责；其他 agent 如有必要，先另给本次分工预览。
>
> **能力**：当前已核实什么；什么未知或不可用；有哪些允许的替代。
>
> **预算**：本次总限额，含并行、调试和重试；未知就明示。
>
> **状态/下一步**：草案、待核实或待授权；只列一个最值得先解决的缺口。
>
> **证据/经验**：关联本项目已有产物与反例；没有记录就写暂无，不补造成功历史。

可直接要求：“按工作流卡简短展示”“展开步骤和验收”“只看现在卡在哪里”“按新条件改成 v2”。短任务可以省掉无关字段。

如果适配的配方已有记录，先显示最相关的一条，并说明本次哪些条件不同；需要比较时再展开其他候选。它是对话中的简短提示，不是系统推送通知，也不代表已经开始派发。

## 我们的经验怎样留下来

现有机制可以把获准的实际产物、核验记录和反馈提炼成配方：

`实际记录 → 一条候选改动 → 相近任务试用 → 核对质量与代价 → 同意保存 → 条件变化时复审`

- **项目事实**：工具当前怎样调用、输入正本在哪里、哪些检查真的通过；只写到获准的项目正本。
- **常用工作流**：适用/不适用条件、角色与交接、验收、费用与停止条件、证据和反例。实际保存位置须由用户指定或沿用已授权私有正本，不写入公开技能仓库。
- **通用技能改进**：从多次经验中形成候选，查依据、看实际差异、做行为回归和备份，再更新技能。一次顺利或一次失败不能直接改全局规则。

当前已有一条值得复用的工程经验：核正本版本 → 分清已读/已运行/已核验 → 最小改动 → 情景与产物检查 → 备份 → 更新 → 检查真实结果。它可以作为构筑配方的参考；不能因此声称某个 agent 搭配已经多次验证最优。

保存配方不等于批准本次执行。已获准运行内部的步骤无需逐个重问；更换参与者、供应商、资料范围、写入目的地或超限费用时，更新预览。个人配方与聊天原文不随通用技能上传 GitHub。

## 让提示更省心

建议采用“按需一行提示 → 一张工作流卡 → 必要时展开步骤”。例如：“这个任务适合用本项目的论文实验配方；先看这次预览。”普通答疑和续课直接进行，用户说直接做就省略不必要介绍；派发仍按本次授权处理。

这页展示的是推荐交互样式。v0.7 已有意图路由、工作栈预览和经验适配规则，但未新增命令面板、自动弹窗、持久化数据库或常驻推荐服务。

## 设计依据

[Agent Workflow Memory](https://arxiv.org/abs/2409.07429)研究从经验提炼并选择性复用流程，评估场景是网页任务，不能直接证明 IM 的个人科研效果。[Anthropic 的 Building effective agents](https://www.anthropic.com/research/building-effective-agents)支持从简单可组合流程开始、按实际验收增加复杂度。这里的简短卡片与分层提示是 IM 的交互建议，尚无单独效果试验。

[Claude Code 技能文档](https://code.claude.com/docs/en/skills)说明相关技能可由模型按描述选用，也可通过消息开头的 `/skill-name` 直接调用；是否可见仍以当前宿主实际发现和设置为准。
