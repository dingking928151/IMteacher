## Codex审查和发布

1. 核对实际原文/字幕/源码和差异；研究、讲者建议、开源机制与本套件设计分开。证据等级、样本、效应或“看完”声明需实物支持。
2. 审查是否尊重偏好与先独立尝试、帮助记录是否正确、是否检查保持/迁移、预算与日期是否真实、是否引入后台能力的虚假承诺。
3. 新旧规则冲突时直接修正拥有者文件；对受影响真实情境做实际演练。独立评审的遗漏要修复并复查，不把不同题数当独立重复样本。
4. 若修改共享协议，分发同一份到四组件；运行validate_bundle和四技能quick_validate，再查具体行为。
5. 记录来源取舍、修订日期、限制和验证；安装前备份，复制后逐文件核对哈希。任何外部写入仍走当前会话授权，不借其他代理绕过权限。
